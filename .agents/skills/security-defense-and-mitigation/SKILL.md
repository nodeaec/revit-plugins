# Security Defense & Mitigation for Revit Add-ins

This skill defines the security-by-design requirements for Autodesk Revit add-ins and Node.aec client-side integrations. All code touching licensing, cryptographic verification, hardware identity, or local storage must strictly adhere to these pillars.

---

## 🛡️ Core Security Pillars

### 1. Asymmetric Cryptography (Ed25519 SPKI)
- **Zero Private Key Exposure**: The client application and repository must **NEVER** contain or transport private signing keys. The client ships only the public Ed25519 SPKI key (`DefaultPublicKeyPem`).
- **Signature Integrity (RFC 8032)**: Leases are signed by the Node.aec server using Ed25519. The client verifies the signature before trusting any payload fields (`exp`, `mid`, `prd`, `seats`).
- **Offline Tamper Resistance**: Any tampering with the cached lease token or expiration date invalidates the cryptographic signature, causing verification to fail closed.

### 2. Hardware Binding & Windows DPAPI
- **Machine Lock Derivation**: The machine identifier (`mid`) must be generated by hashing the Windows `MachineGuid` and `MachineName` via SHA-256. Never rely on easily spoofed environment variables alone.
- **Local Storage Encryption (DPAPI)**: Stored lease tokens on disk must be encrypted using `ProtectedData.Protect(bytes, entropy, DataProtectionScope.CurrentUser)`. This ensures:
  - Tokens cannot be copied and used by other user accounts on the same machine.
  - Tokens cannot be extracted to another workstation.

### 3. Fail-Closed Commercial Protection
- **Default Deny**: If a network call fails and the local cached lease is expired or invalid, commercial commands must **deny execution by default** (`fail closed`). Never silently allow execution on security errors.
- **Clock Drift & Rollback Defense**: Reject tokens if the client machine clock is earlier than the token's issued-at timestamp (`iat`) or later than expiration (`exp`).

### 4. Zero Data & Token Leakage
- **No Stack Traces in UI**: Never expose raw exceptions, database errors, or internal file paths inside Revit `TaskDialog` or WPF popups. Display clear domain messages (e.g. *"Não foi possível validar sua licença. Verifique sua conexão."*).
- **Sanitized Logging**: Ensure bearer tokens, license keys, and raw DPAPI byte buffers are never written to plain-text log files.
- **Memory Hygiene**: Once license checks complete, avoid holding decrypted token strings in static long-lived references.

### 5. Network & Transport Security
- **Enforce HTTPS**: All communication with the Node.aec platform must use HTTPS (`https://api.nodeaec.com.br`). Never allow plaintext HTTP fallback.
- **Input Sanitization**: Validate license keys using regular expressions (`^NAEC-[A-Z0-9]{4}-[A-Z0-9]{4}-[A-Z0-9]{4}-[A-Z0-9]{4}$`) before dispatching HTTP requests to avoid unnecessary load or injection risks.
- **Path Traversal Prevention**: When loading icons or file assets, sanitize and resolve absolute paths inside the plugin directory. Never use untrusted input to construct file paths.

## ✅ Security Validation Checklist

- [ ] Only public keys (`MCowBQYDK2VwAyEArMYcaZMAlBeimfR6twrHZndEWOSaIHlSURYFhTjalMg=`) exist in client code.
- [ ] Stored lease tokens are encrypted on disk via Windows DPAPI (`ProtectedData`).
- [ ] Machine identity is derived via cryptographic SHA-256 hashing.
- [ ] API endpoints are strictly HTTPS pointing to production (`https://api.nodeaec.com.br`).
- [ ] License checks fail closed (deny execution) when tokens are invalid or expired.
- [ ] No sensitive tokens or stack traces are displayed to users in dialogs.
